# 주식 자동매매 프로그램

국내(KOSPI/KOSDAQ) + 미국 주식을 대상으로 하는 PC 데스크톱 자동매매 프로그램.
신호 알림 → 모의투자 → 실매매 순서로 단계적으로 전환한다.

## 핵심 원칙 (반드시 지킬 것)

- **실계좌 주문(LiveExecutor)은 사용자가 명시적으로 요청하기 전까지 절대 구현·활성화하지 않는다.** 기본값은 항상 NotifyExecutor.
- API 키, 계좌번호 등 비밀 정보는 `.env`에만 저장하고 코드·로그·커밋에 절대 넣지 않는다. `.env`는 `.gitignore`에 포함.
- 모든 시각은 timezone-aware로 처리한다. 국내는 Asia/Seoul, 미국은 America/New_York (서머타임 자동 반영).
- 리스크 가드 로직에는 반드시 단위 테스트를 작성한다. 리스크 가드를 우회하는 주문 경로는 만들지 않는다.
- 백테스트는 항상 수수료·세금·슬리피지를 반영한다. 신호를 계산한 봉의 종가로 체결시키지 않는다(look-ahead 금지).
- 전략 파라미터는 코드에 하드코딩하지 않고 `config/strategy.yaml`에서 읽는다.

## 기술 스택

- 코어: Python 3.11+ (pandas, numpy)
- 로컬 API: FastAPI (코어 ↔ UI 통신)
- UI: Tauri + 웹 프론트엔드 (또는 PySide6 단일 스택 — UI 단계에서 결정)
- 저장소: 시세는 Parquet, 주문·체결·설정·로그는 SQLite
- 알림: 텔레그램 봇
- 배포: PyInstaller로 코어 번들링

## 아키텍처

```
데스크톱 UI (대시보드 · 설정 · 로그)
        │
로컬 코어 (Python)
  ├─ 전략 엔진   : 시세 → 매매 신호
  ├─ 리스크 가드 : 신호 검증 (비중, 손실 한도, 보유 수)
  └─ 실행 어댑터 : Notify / Paper / Live
        │
브로커 추상화 레이어 (Broker 인터페이스)
  ├─ 국내 구현체
  └─ 해외 구현체
```

### Broker 인터페이스

전략 엔진과 리스크 가드는 이 인터페이스만 사용한다. 증권사별 코드는 구현체 안에만 존재한다.

```python
class Broker(Protocol):
    def get_candles(self, symbol, interval, start, end) -> DataFrame: ...
    def get_quote(self, symbol) -> Quote: ...
    def get_balance(self) -> Balance: ...
    def get_positions(self) -> list[Position]: ...
    def place_order(self, symbol, side, qty, order_type, price=None) -> OrderId: ...
    def cancel_order(self, order_id) -> None: ...
```

1차 증권사 후보: 한국투자증권 Open API (국내·해외 모두 지원). 모의투자 서버 먼저 사용.

### Executor

같은 인터페이스(`execute(signal)`)의 세 구현체. `config/app.yaml`의 `executor:` 값 하나로 교체.

- `NotifyExecutor`: 텔레그램으로 신호만 전송 (기본값)
- `PaperExecutor`: 모의투자 계좌로 주문
- `LiveExecutor`: 실계좌 주문 — 사용자 요청 전까지 미구현

## 운용 조건

| 항목 | 값 |
|---|---|
| 운용 자금 | 국내 1,000,000원 / 해외 1,000,000원 (각각 독립 계좌로 관리) |
| 최대 낙폭(MDD) | -10% 도달 시 해당 시장 전체 매매 정지 + 알림 |
| 거래당 리스크 | 계좌의 1% |
| 일일 손실 한도 | -3% 도달 시 당일 신규 진입 중단 |
| 연속 손절 | 4회 연속 손절 시 당일 매매 중단 + 알림 |
| 최대 동시 보유 | 시장별 2종목 |
| 운영 시간 | 국내 장중 + 미국 장중(한국 밤~새벽) 모두 PC 상시 가동, 절전 방지 필요 |

## 전략: 시가 범위 돌파 (Opening Range Breakout) + 분할 익절

장 시작 후 일정 시간의 고가·저가 범위를 기준으로, 거래량을 동반해 범위 상단을 돌파하면 진입한다.
단타로 시작해 1차 익절에 성공한 종목만 스윙으로 끌고 가는 구조.
**아래 수치는 초기값이며 백테스트로 검증·조정한다.**

### 유니버스 (매일 장 시작 전 자동 선정)

국내:
- 시가총액 1,000억 원 이상
- 전일 거래대금 100억 원 이상
- 주가 2,000원 ~ 100,000원
- 제외: 관리종목, 투자경고·위험, 거래정지, 스팩, 우선주, ETF/ETN
- 전일 거래대금 상위 30종목을 감시 목록으로

미국:
- 주가 $5 ~ $100 (분할 익절 가능한 수량 확보)
- 20일 평균 거래대금 $20M 이상
- 보통주만 (ETF, ADR, OTC 제외)
- 프리마켓 거래량 상위 + 갭 +2% 이상 종목 중 상위 20개를 감시 목록으로

### 진입 조건 (5분봉 기준)

```
시가 범위(OR) = 장 시작 후 첫 15분의 고가 / 저가

IF   5분봉 종가 > OR 고가                      (범위 상단 돌파)
AND  현재가 > 당일 VWAP                         (당일 매수세 우위)
AND  당일 누적 거래량 > 최근 20일 같은 시각 평균 × 2   (상대 거래량)
AND  시가 갭 0% ~ +8%                           (과도한 갭 제외)
AND  국내: 현재가 < 상한가 × 0.9                 (상한가 근처 제외)
AND  진입 가능 시간대 안
THEN 다음 봉 시작 시 지정가(현재 매도호가) 매수

진입 가능 시간대:
  국내 09:15 ~ 11:00 (KST)
  미국 09:45 ~ 11:30 (ET)
```

### 청산 조건

```
손절: 진입가 -2% (또는 OR 저가 중 진입가에 더 가까운 쪽)

+3% 도달 → 보유 수량 50% 익절, 잔량 손절선을 진입가(본전)로 상향
+5% 도달 → 잔량 전량 익절

1차 익절 전인데 장 마감 15분 전 → 전량 청산 (단타 정리)
1차 익절 후 잔량 → 오버나잇 보유 허용, 최대 3거래일
  3거래일째 장 마감 15분 전까지 미청산 시 → 전량 청산
```

### 포지션 크기

```
매수 수량 = floor((계좌 평가금 × 1%) ÷ (진입가 − 손절가))
단, 1종목 투입금 ≤ 계좌의 50%
수량이 2주 미만이면 진입하지 않음 (분할 익절 불가)
```

### 비용 가정 (백테스트용, 실제 값은 증권사·연도 기준으로 확인 후 수정)

- 국내: 매수·매도 수수료 + 매도 시 거래세, 슬리피지 0.1%
- 미국: 매수·매도 수수료 + 환전 스프레드, 슬리피지 0.1%

## 개발 순서

각 단계는 완료 기준을 만족해야 다음으로 넘어간다.

1. **프로젝트 뼈대**: 폴더 구조, 설정 로더, 로깅, Broker/Executor 인터페이스 스텁
   - 완료: `pytest` 통과, 설정 파일에서 전략 파라미터 로드 확인
2. **데이터 수집**: 한국투자증권 API 연동 (모의 서버), 국내·미국 분봉 수집 → Parquet 저장
   - 분봉 과거 데이터는 증권사가 제공하는 기간이 짧을 수 있으므로 **수집기를 가장 먼저 매일 돌려 데이터를 쌓기 시작**한다
   - 완료: 감시 종목 5분봉이 매일 자동 적재됨
3. **전략 엔진 + 리스크 가드**: 유니버스 선정, 진입·청산 신호, 포지션 사이징, 계좌 리스크 룰
   - 완료: 리스크 가드 단위 테스트 전부 통과
4. **백테스트**: 비용 반영, 결과 지표 (총수익, MDD, 승률, 손익비, 평균 보유 기간, 거래 횟수)
   - 완료: 국내·미국 각각 결과 리포트 생성. 파라미터 조정은 사용자와 상의
5. **NotifyExecutor**: 실시간 감시 → 신호 발생 시 텔레그램 알림
   - 완료: 2주간 장중 무중단 운영, 알림 신호와 백테스트 신호 일치 확인
6. **PaperExecutor**: 모의투자 자동주문, 주문 상태 관리(대기/부분체결/체결/취소), 중복주문 방지, 재접속 처리
   - 완료: 모의투자 2주 이상 운영, 백테스트 대비 괴리 분석
7. **데스크톱 UI**: 대시보드(보유·손익·오늘 신호) → 전략 설정 → 백테스트 결과 → 주문 로그
8. **패키징**: PyInstaller + UI 번들, 절전 방지, 자동 재시작, 킬스위치 버튼
9. **LiveExecutor**: 사용자가 명시적으로 요청할 때만. 소액·단일 종목부터.

## UI 명세 (7단계)

디자인 확정본. 화면을 새로 만들지 말고 이 구조를 따른다.

### 레이아웃

- 좌측 사이드바 248px 고정(어두운 배경) + 상단 바 64px 고정 + 본문
- 기준 해상도 1440×900, 최소 1280×800

### 상단 바 (모든 화면 고정)

`[긴급 정지]` · 모드 배지 · 증권사 연결 상태 · 장 시간(우측)

- 긴급 정지: 신규 주문 중단 + 미체결 전량 취소. 보유 청산 여부는 리스크 설정의 체크박스를 따른다.
- 실전 모드일 때 상단 바 배경을 붉은 톤(`#FDF2F2` / 테두리 `#E8BFBF`)으로 바꾼다.

### 사이드바 메뉴

```
운영    대시보드 · 매매 운영 · 감시 종목 · 주문·체결 내역
전략    조건식 · 백테스팅
분석    이력·성과 · 계좌정보
시스템  리스크 설정 · 로그·알림 · 설정
```

실전/모의는 별도 메뉴가 아니라 **매매 운영 화면 안의 토글**이다. 화면을 두 벌 만들지 않는다.

### 화면별 필수 요소

| 화면 | 담는 것 |

| 대시보드 | 지표 4종(오늘 실현손익·평가손익·계좌 평가금·승률), 리스크 게이지 3종 + 연속 손절 카운터, 보유 종목 표, 오늘의 신호 목록 |
| 매매 운영 | 모의/실전 토글, 국내/미국 토글, 적용 조건식, 실행·중지 버튼, 엔진 상태 4종, 주문·체결 현황, 차단된 신호 목록, 실행 로그 |
| 조건식 | 좌측 목록, 진입 조건 행 편집, 청산 조건 행 편집, 유니버스 요약, 직전 백테스트 요약 |
| 백테스팅 | 실행 조건 바, 지표 6종(비용 차감 포함), 누적 수익 곡선, 청산 사유 분포, 파라미터 민감도 |
| 이력·성과 | 전체/모의/실전 · 국내/미국 필터, 월별 손익 막대, 조건식별 성과 비교, 매매 이력 표, CSV 내보내기 |
| 리스크 설정 | 계좌 한도 4종, 포지션 한도 3종, 현재 사용량 게이지, 긴급 정지 동작 체크박스 |

### 색·서체 규칙

- 수익·매수 `#C6282C`(적) / 손실·매도 `#1859C4`(청). 국내 증권사 관행.
- 강조색은 색이 아니라 먹 `#16181D`. 파란 버튼은 손실로 오독되므로 쓰지 않는다.
- 배경 `#F5F4F0`, 카드 `#FFFFFF`, 테두리 `#E2E0DA`, 본문 `#16181D`, 보조 `#4A4E57`, 흐린 글씨 `#6B7078`(그보다 밝은 회색은 대비 미달)
- 본문 IBM Plex Sans KR, **모든 숫자는 IBM Plex Mono**(자릿수 정렬)
- 게이지: 여유 `#2E7D4F` / 주의 `#D97757` / 한도 도달 `#16181D`

### UI 규칙

- 조건식이 실전에 적용 중이면 편집 잠금. 백테스트 → 모의 2주를 통과해야 실전 목록에 뜬다.
- 리스크 설정은 조건식 화면에서 수정할 수 없다(별도 화면에서만).
- 미구현 메뉴는 숨기지 말고 흐리게 표시한다.
