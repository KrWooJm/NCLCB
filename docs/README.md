# 로또 6/45 데이터 분석기

동행복권 전 회차 당첨 데이터를 **매주 자동 수집**해 통계 분석하고, 예산(기본 5만원 = 50게임)에 맞춘
구매 조합을 생성하는 정적 웹사이트입니다.

## 이 도구가 주장하는 것과 주장하지 않는 것

**주장하지 않습니다** — 과거 데이터로 당첨 확률을 높이는 방법은 존재하지 않습니다.
로또는 매 회차 독립시행이며, 모든 조합의 확률은 동일하게 1/8,145,060 입니다.

**주장합니다** — 확률은 못 바꿔도 다음 두 가지는 통제할 수 있습니다.

| 최적화 대상 | 방법 | 효과 |
|---|---|---|
| 당첨 시 분할 인원 | 인기 조합(생일 편중·연속수·등차수열·과거 당첨번호) 회피 | 기대 수령액 ↑ |
| 포트폴리오 분산 | 50게임이 서로 최대 2개까지만 겹치도록 생성 | 하위 등수 당첨 분포 개선 |

인기 조합 회피의 근거는 추측이 아니라 **1등 당첨자 수** 실측 데이터입니다. 1등 당첨자 수는
"그 조합을 몇 명이 샀는가"의 직접 관측치이므로, 판매액으로 정규화하면 조합 유형별 인기도를
실제로 측정할 수 있습니다.

그리고 이 사이트 자신의 전략을 포함한 모든 전략을 **과거 전 회차 백테스트**로 검증해
결과를 그대로 공개합니다 (미래 정보 누수 차단: N회차 예측에는 N회차 이전 데이터만 사용).

## 구조

```
docs/                   GitHub Pages 로 서빙되는 정적 사이트
  index.html            페이지
  engine.js             확률·통계 검정 (카이제곱, z-검정, 시드 난수)
  analysis.js           회차 분석 · 인기도 실증 · 번호 생성 · 백테스트
  charts.js             의존성 없는 SVG 차트
  app.js                화면 렌더링
  data/draws.js         당첨 데이터 (자동 생성 — 직접 수정 금지)
scripts/update_draws.py 동행복권 공식 API 수집기 (증분 갱신)
.github/workflows/update-lotto.yml  매주 자동 실행
```

## 자동 갱신 방식

추첨은 매주 토요일 20:45 KST. 워크플로가 **일요일 00:10 KST** 에 실행되어 신규 회차를
수집하고 `docs/data/` 를 커밋합니다. 1242회, 1243회… 가 쌓일 때마다 사이트의 모든 분석이
새 데이터로 다시 계산됩니다.

> **중요:** GitHub 의 `schedule` 이벤트는 **기본 브랜치(main)에 있는 워크플로만** 실행합니다.
> 자동 갱신이 매주 돌게 하려면 이 브랜치를 `main` 에 병합해야 합니다.
> 병합 전에는 Actions 탭 → *로또 당첨번호 자동 갱신* → **Run workflow** 로 수동 실행할 수 있습니다.

## 로컬 실행

```bash
python3 scripts/update_draws.py     # 데이터 수집 (최초 실행 시 1회차부터 전체)
python3 -m http.server 8000 -d docs # http://localhost:8000
```

`--rebuild` 옵션을 주면 1회차부터 다시 수집합니다.

## GitHub Pages 설정

저장소 **Settings → Pages** 에서 Source 를 `Deploy from a branch`, 브랜치를 배포할 브랜치의
`/docs` 폴더로 지정하면 사이트가 공개됩니다.
